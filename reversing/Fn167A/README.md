## Revision contra el EXE (desensamblado del EXE canonico, `exe_full_116.dis`)
- **0x4C5750** (thiscall, `ret`): `mov dword [ecx],85BB9Ch`. Solo deja la vtable de la clase base (CBaseModelInfo) y no llama a nada, igual que 0x4C5590 (CAtomicModelInfo) y 0x4C5620 (CBaseModelInfo). Lo pasan a los iteradores de vectores de los almacenes (`push 0x4C5750` en 0x4C5900 y 0x4C5EF1), lo llama 0x4C62B3 y hay un salto 0x83BC23.
- **0x4C5760** (thiscall, `ret`): `push esi; mov esi,ecx; call 4C4A60; mov [esi],85BD78h; mov eax,esi; pop esi; ret`. La vtable 0x85BD78 es la de `CWeaponModelInfo` (el propio codigo la declara); 0x4C4A60 es el constructor base de CBaseModelInfo (con hook desde el lote 143A). Devuelve `this`.
- **0x4DC2A0** (thiscall, `ret`): `mov eax,[ecx+4]; push eax; mov byte [ecx+0Ch],0; call [858078h]` (CloseHandle en la IAT del EXE). El byte `m_bIsOpen` se limpia **antes** de llamar y EAX es el del propio CloseHandle (BOOL completo, no normalizado a 0/1). Unica referencia estatica: el `jmp 0x4DC2A0` de 0x5025DC (`CAEVorbisDecoder::CloseCallback`, que ya devolvia el resultado de `Close()`). `CAEDataStream::Close()` pasa de `bool` a `BOOL` para devolver EAX completo.
- **0x4DC550** (thiscall, `ret 4`): vtable 0x85F0BC en `[this]`; si el BYTE +0Ch no es cero lo pone a 0 y llama a CloseHandle con el HANDLE de +4; si el nombre (+8) no es nulo llama a `operator delete` (0x8214BD) y lo pone a 0; si el bit 0 del BYTE de banderas (pila) esta puesto llama a `operator delete` sobre `this`; devuelve `this`. Es el cuerpo de `~CAEDataStream` (0x4DC490) mas la liberacion; no tiene llamadores estaticos ni esta en la vtable IStream (que no tiene destructor virtual), por lo que solo se ejerce desde el banco. `RH_ScopedVMTInstall` no puede nombrar una ranura inexistente: se engancha como S con `RH_ScopedNamedGlobalInstall`.
