## Que hace cada una (desensamblado leido del EXE)
- **AddWheelSand / AddWheelDust (0x4A0610..0x4A09B4 / 0x4A09C0..0x4A0D64).** Siempre llama a `FindPlayerVehicle(-1,false)` (0x56E0D0). `s = (dz*dz + dy*dy) + dx*dx` (camara - pos, 24 bits), guardada como float; sale si `s > 625` o NaN (`jp`). Cadencia: `clave = (int16)modelo(+0x22) + CTimer::m_FrameCounter`; calidad `this+0x54 >= 1`: sale si `clave&1`, y si `s > 64` o no hay vehiculo del jugador exige `clave&3 == 0`; calidad 0: `clave&3 == 0`, y con `s > 64`/sin vehiculo `clave&7 == 0`; calidad negativa: siempre. Multiplicador base (arena 0.81/0.67/0.57, polvo 0.51/0.44/0.31; alfa 0.5; tamano y vida sustituidos). `A = |pedal(+0x49C)|`; t = 1.0 si el byte de giro, si no `min(2*|v|, 1)` (|v| = norma de `+0x44` con fsqrt; NaN conserva 2*|v|); vida (arena `(1+t)*0.1f`, polvo `0.05f*t + 0.1f`), tamano `(0.9f*t + 0.1f)*{0.25 BMX, 0.5 moto/quad, 0.7}` y `q = 2.0` (BMX, moto, quad) o `1.5`. Numero de particulas = `max(1, EAX de _ftol2(sqrt((vz'*vz + vy'^2) + vx'^2) * q))` con `v' = float(v*paso)` (vz' en registro para el primer producto) y comparacion con signo. Por particula (3 `rand()` del CRT del EXE, 0x821B1E): velocidad `(r*3.05e-5f) * ((A*v)*-40.0f)` en x/y y `(r*3.05e-5f)*base + 0.2f` en z (`base = (t+0.8f)-0.2f`); posicion `pos - v'*w` con `w = 1.0 - i/float(n)` (x con el producto en registro; y, z guardados como float). `AddParticle` sobre `g_fx.m_Sand` (0xA9AE18, releido en cada vuelta), luz `lightMult`, limite 0.7f.
- **AddWheelGrass / Gravel / Mud (0x49FF20 / 0x4A0170 / 0x4A03C0).** Solo actua si el conductor (+0x460) es `FindPlayerPed(0)` o, tras una segunda llamada `FindPlayerPed(1)`, ese; despues `FindPlayerVehicle(-1,false)` y `s` (en registro). Sale si `s > 625` o NaN; `s > 400`: `(byte bajo del modelo + contador)&3`; `s > 64` o sin vehiculo del jugador: `&1`; si no, siempre. Tres particulas, seis `rand()` cada una (tamano, vel x, y, z, pos x, y); `g_fx.m_WheelDirt` (0xA9AE3C), limite 0.6f. Solo cambia el color base (hierba 0.03/0.09/0.03 vida 0.05; grava 0.25 x3; barro 0.25/0.12/0.06).
- **AddDebris / AddGlass (0x49F750 / 0x49F970).** Sale si `(dz2+dx2)+dy2 > 625` (NaN no sale). Color RwRGBA * (1/255), tamano = `escala` (copia sin pasar por la FPU), un `rand() % 10000` (se consume aunque `amount <= 0`) para `rot = (r*1e-4f + 1)*0.5f`, vida 0.2f. Por vuelta tres `rand()` (velocidad x, y `((r*3.05e-5f)*0.5f)*20 - 5`, z `((r*3.05e-5f)*0.15f)*20 + 2`); AddDebris activa las primitivas 0..3 en falso y la primitiva del contador estatico del EXE (0xA9ADE4, `(c+1)&3`) con `EnablePrim` (0x4AA610) sobre `g_fx.m_Cardebris`; AddGlass solo `AddParticle` sobre `g_fx.m_Glass`. Luz 1.2f, limite 0.6f.
- **TriggerGunshot (0x4A0DE0).** Sale si `(dz2+dx2)+dy2 > 625` (origen). Con entidad: desplazamiento = origen - posicion (matriz+0x30 o transformacion simple+4, **leida antes** de crear la matriz), si no hay matriz `AllocateMatrix` (0x54F560) + `CSimpleTransform::UpdateMatrix` (0x54F1B0); el desplazamiento se multiplica por la matriz de la entidad (Multiply3x3 vector*matriz, 0x59C810, ya reconstruido como `FlcMatInvMul3x3`) y **sustituye** al desplazamiento; si el objeto RenderWare (+0x18) es nulo termina; la matriz padre es la de modelado del marco (`[obj+4]+0x10`). Sin entidad: `FxRwMatrixCreate` (0x4A9440) + `CreateMatFromVec` (0x49E950, origen/destino) y desplazamiento cero. Con matriz padre no nula: "gunflash" (solo si el byte de fogonazo es no nulo) y siempre "gunsmoke" con `CreateFxSystem` (0x4A9BE0); cada sistema devuelto se reproduce con `PlayAndKill` (0x4AA3D0) y, sin entidad, antes `CopyParentMatrix` (0x4AA890). Al final `FxRwMatrixDestroy` (0x4A9460) de la matriz creada.
