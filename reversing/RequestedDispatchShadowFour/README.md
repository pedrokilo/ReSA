# Dispatch and shadow return: prepared CPU bank

Prepared only. No build, execution, validation approval or registry change is claimed.

Targets are CCustomBuildingRenderer::Initialise (0x5D7EC0), Shutdown (0x5D7EE0), PluginAttach (0x5D7EF0), and CRealTimeShadowManager::ReturnRealTimeShadow (0x705B30). There are 1,024, 1,024, 1,024 and 2,048 pairs respectively, 5,120 total. Fresh target combo dossiers supplied by the coordinator were copied into evidence; helper dossiers were obtained with reversing/_handoff/combo.sh. Both EXE locations used by combo and runtime were hashed as 72ae59e44c761389e354a50dc6215e964fe771121e2f4b1877273a493ceecc9b.

The native CreatePipe helpers (0x5D7D90 and 0x5D7100) both finish SETNE CL followed by MOV EAX,ECX after XOR ECX,ECX: their actual returns are canonical 0/1, despite their internal pointer-valued pipeline creation. ExtraVertColourPluginAttach also normalizes both epilogues through SETNE CL/MOV EAX,ECX. Current source signatures are bool, checked at compile time. EXE helper stubs return int32 0/1 and DLL helper stubs return bool 0/1; the target bool is captured as raw AL, without masking or truth-normalizing its result. Unreachable noncanonical helper return values are not injected or credited as semantic coverage.

Dispatch fixtures enumerate both first-create statuses, both second-create statuses and 256 private payloads for Initialise, verifying short circuit and helper order. Plugin enumerates both statuses and 512 payloads. Shutdown verifies both destroy calls in native order, including the tail-called second helper, over 1,024 private payloads. Stubs log helper role/status/token, change only their declared private byte and preserve the other payload bytes. Model traces and payload effects are re-derived independently by oracle.py; agreement between original and candidate alone cannot approve a pair. The helpers themselves, actual pipeline allocation/destruction and RenderWare/plugin registration receive no validation credit.

ReturnRealTimeShadow uses aligned, guarded, private representations of the typed manager (0x54), shadow (0x4C) and CPhysical (0x138). Runtime layout gates check manager.initialized+0, shadow.owner+0 and physical.shadow+0x134. The native body reads only these fields. Init is exactly 0/1. A null shadow or owner occurs only when init=0; initialized cases always have a live private owner. Full representations and guards are compared; when initialized the independent byte model clears precisely shadow.owner and physical.shadow, leaving every other byte intact. Other bytes deliberately use raw stress patterns, including noncanonical representations of fields the target never reads. These fixtures do not construct gameplay objects, run destructors or certify their other fields/lifetimes; they exercise the x86 ABI and two pointer writes. Invalid null arguments when initialized would fault in the native implementation and are outside this safe fixture domain.

The pregraphics harness snapshots and restores flags and 52 bytes of both EXE/DLL entries for every installed simple and virtual hook, full known native/DLL vtable ranges and the timer block. Unknown vtable metadata prevents execution. The bank snapshots its collaborator entry ranges before unhooking, waits until every EntryPatch destructor has completed, restores all flags and then verifies all ranges byte for byte. Private payload and three real pipeline/plugin global fields are snapshotted, restored and checked; any unexpected write to those real globals rejects the bank. FP environment is saved and restored, with measured x87 status/control and MXCSR comparison. There is no fixed state_restored=true acceptance record.

Only the coordinator runs build_probe.py and run_local.py, serially. The builder records all source CPP/headers, build configuration, private instruments/evidence/oracle and shared snapshot/runner helpers; it verifies hashes again after compilation. WinMain is injected temporarily, its compiled fingerprint is retained and its original bytes and normal ASI/PDB are restored in finally. Debug uses _CL_=/MP6 and one build scheduler process. The runner rejects changed source/instruments/WinMain, wrong canonical EXE, changed archived ASI/PDB, missing/duplicate fixtures, any oracle mismatch, failed restoration and failed natural process exit. Failed attempts and logs are preserved. No graphics, pipeline integration, startup or gameplay campaign is credited.
