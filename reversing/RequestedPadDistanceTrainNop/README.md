Preparation only: no compilation, GTA execution, validation approval or registry update.

There are 13,952 pairs: ProcessPCSpecificStuff 0x53FB40 (1,024), StartShake_Distance 0x53F9A0 (10,240), and StartShake_Train 0x53FA70 (2,688). Fresh combo exports and independently decoded complete function bytes/assembly are in evidence. The runtime and combo EXE copies both match canonical SHA-256 72ae59e44c761389e354a50dc6215e964fe771121e2f4b1877273a493ceecc9b. Combo lacks retained pseudocode for Train/NOP; its fallback includes following functions, so the exact complete boundaries are instead the independent files: Distance [0x53F9A0,0x53FA63), Train [0x53FA70,0x53FB40), and NOP [0x53FB40,0x53FB41).

## ABI prerequisite and negative baseline

At preparation, Pad.h and Pad.cpp declare StartShake_Train(const CVector2D&). The native body reads two float stack arguments and ends RET 8 at 0x53FB3D. The reference signature is incompatible. Fixtures.hpp has a static assertion requiring void(CPad::*)(CVector2D), and the builder refuses the reference signature before touching sources/artifacts. A coordinator-owned ABI-only correction is required before compiling. This bank never invokes the incompatible current candidate. Source snapshots before that correction are preserved in evidence/Pad.h.before-ABI.txt and Pad.cpp.before-ABI.txt.

After the coordinator builds, check_train_abi.py reads the matching current ASI/PDB through VS DIA metadata, finds the unique compiled Train body and preserves its full assembly/bytes. Every RET must consume eight bytes. The runner gates the hashed proof and matching artifact identities before execution. The ASI is never loaded by the static checker.

The native Train body calls FindPlayerVehicle(-1,false) once if null, twice if nonnull, and exits when vehicle.type == 6 (TRAIN). A null or nontrain vehicle continues into 2D distance. The preparation-time source has the opposite gate: it returns for null/nontrain and continues for TRAIN. That difference is deliberately left visible for the coordinator's ABI-correct negative baseline. Trace multiplicity/order is compared exactly; nothing is normalized to hide a difference. A negative baseline cannot approve the function.

## Fixtures and oracle

Distance enumerates 16 signed old/request-duration pairs, frequencies 0/1/127/128/255, four vibration/cutscene gate combinations, compact/matrix camera position and 16 geometries. Signed edges include -32768, -1, 0, 1, 99, 100 and 32767. Geometry includes zero, positive/negative axes, 70 under/exact/over through nextafter, XY tangency 42/56 and finite XYZ components. Four finite camera origins are selected by duration role; all input float bits are logged. Train enumerates seven stored durations, null/nontrain/train vehicles, four gates, two camera modes and those same geometries; Z is intentionally present but ignored by native Train. NOP preserves all private pad bytes and global regions without inventing an EAX return contract.

Execution explicitly uses x87 PC24, round nearest, masked exceptions and MXCSR 0x1F80. Model arithmetic is separately transcribed from the native instructions (Distance z²+y²+x² then FSQRT; Train y²+x², stored to float, FSQRT, 70-minus-distance-plus-30 and truncation). oracle.py independently recomputes every finite operation with binary32 rounding using Python arithmetic, validates the generated fixture product and all input bits, reconstructs pad byte writes and the exact FindPlayerVehicle trace, and checks the model's sum/magnitude bits. Original/candidate agreement alone is insufficient. Post-call control, sticky exceptions and MXCSR must also match between routes; initial/full FP state is restored and measured at completion. x87 comparison-condition bits after each function are not an ABI return and are not credited as semantic equivalence; raw status is retained for restoration.

Private CPad fixtures begin a real object lifetime by copying the existing CPad::Pads[0] object, avoiding CPad() and its Clear() effects on global keyboard/mouse histories. Raw pad stress preserves canonical bool fields; only the target's signed duration and frequency fields are subsequently read. A real local CMatrixLink has a live constructor/destructor, canonical zeroed pointer/bool representation, finite basis/position and no attached or owned RenderWare resources. The real camera borrows that matrix only within its lifetime; its full representation is restored before the private matrix dies.

The FindPlayerVehicle collaborator returns either nullptr or a guarded CVehicle-sized ABI image whose sole accessed field is the int32 type at +0x590. It is explicitly an ABI image, not a constructed gameplay vehicle; no constructors, destructors, virtual dispatch or ownership APIs are invoked on it. Layout is checked against the typed declaration, all bytes and guards are checked unchanged, and this fixture does not certify other CVehicle fields or real-vehicle integration. Native and DLL helper entry JMP targets are checked exactly against the private callback. No helper implementation receives credit, and no target is stubbed.

Full camera bytes, vibration/cutscene neighboring regions and both real CPad globals are snapshotted. Each pair seeds identical states, checks full readonly images/guards, and records original/candidate physical outputs. All hook flags and 52 bytes of every installed native/DLL entry, known vtables, timer, and both helper patch ranges are restored and verified; EntryPatch destructors run before terminal acceptance. FP environment/status/control/MXCSR are restored. The outer pregraphics harness performs its own full restoration check.

Only the coordinator runs build_probe.py/run_local.py, after the source ABI correction and preceding active source work. Builder captures the final complete source/configuration inventory and instrument/evidence hashes, uses Debug _CL_=/MP6 and one scheduler process, and restores WinMain and normal ASI/PDB. Runner rejects stale source/instruments/WinMain or ASI/PDB, missing/duplicate fixtures, independent model differences, failed restoration or missing natural exit. Every attempt and old rebuild artifact is preserved. This does not approve WinMain/startup, camera resource ownership, rendering, FindPlayerVehicle implementation or real gameplay.
